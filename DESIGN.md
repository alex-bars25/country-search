# DESIGN.md

## 1. Отмена устаревших запросов

При каждом `update()` в `searcher.ts` синхронно вызывается
`controller.abort()` — старый запрос обрывается **до** того, как debounce
запустит новый. Внутри `run()` создаётся свой `AbortController`, его сигнал
комбинируется с таймаутом: `AbortSignal.any([own.signal, AbortSignal.timeout(ms)])`.

**Почему `AbortController`, а не флаг `isCurrent`:**

- **Флаг не останавливает сеть.** Запрос продолжает висеть, ответ скачивается
  и парсится впустую. При быстром вводе `s→sp→spa→spain` — 5 лишних запросов.
- **Флаг требует проверки после каждого `await`.** Забыли одну — гонка
  вернулась. `abort()` отклоняет весь промис-чейн автоматически.
- **Флаг не композится с таймаутом.** Пришлось бы держать два независимых
  механизма остановки. `AbortSignal.any` объединяет обе причины, различаем
  их по `err.name` (`AbortError` / `TimeoutError`).
- **`AbortController` — часть платформы.** `fetch`, `AbortSignal.timeout`,
  `AbortSignal.any` понимают его нативно, своего протокола не нужно.

**Различение ошибок:** `AbortError` → молча выходим (отмену инициировал сам
пользователь). `TimeoutError` → `onChange({ kind: 'error' })` (пользователь
ждал и не дождался).

## 2. Задержка debounce: 300 мс

- Средний интервал между нажатиями — 100–200 мс. 300 мс надёжно «схлопывает»
  ввод в один запрос.
- Психологический порог «мгновенного отклика» — до 300–400 мс. Мы на границе:
  задержка ещё не воспринимается как лаг.
- Отраслевой стандарт (Google, Algolia) — 200–350 мс.

**Без debounce (`delay = 0`):** 5 нажатий = 5 запросов, 4 из них заведомо
устарели. Лишний трафик, нагрузка на сервер, расход батареи на мобильной сети.

**Слишком большой (`1500` мс):** пользователь набрал `spain`, ждёт — ничего.
Ощущается как «сломалось», он стирает или уходит.

**Debounce + отмена работают вместе:** debounce гасит запросы во время
печати, отмена — после паузы, если пользователь продолжил ввод. Только
вдвоём дают один запрос на «осмысленное» действие.

## 3. Сложность

`mapCountryResponse(raw)` — по одной стране: **O(L + C)**, где L — число
языков, C — число валют (обычно 1–3). Для `searchCountries` по массиву из N
стран: **O(N · (L + C))**.

## 4. Принципы чистого кода

- **SRP.** Каждый модуль — одна ответственность: `debounce` / `http` /
  `mapCountry` / `searcher` / `ui` / `main`. Тест `searcher` не требует
  `fetch`, тест `ui` не требует `searcher`.
- **Чистые функции.** `mapCountryResponse` (`src/mapCountry.ts`) не мутирует
  вход, детерминирована, без побочных эффектов — тестируется на фикстурах.
- **Dependency Injection.** `createSearcher` (`src/searcher.ts`) принимает
  `search` и `onChange` параметрами — тест подставляет моки без сети и DOM.
  В `main.ts` — реальные реализации.
- **Fail-fast в `http.ts`.** `res.ok` проверяется явно (`fetch` не бросает
  на 4xx/5xx). `HttpError` — класс с `status`, различение через `instanceof`,
  а не по тексту. `404` — отдельная ветка `return []`, не `throw`.
- **Type safety.** `strict`, `noUncheckedIndexedAccess` — `raw.capital?.[0]`
  имеет тип `string | undefined`. `Debounced<Args>` сохраняет сигнатуру `fn`.
- **Immutability.** Все состояния создаются заново; `mapCountryResponse`
  возвращает новый объект.
- **Naming.** Глаголы для действий (`searchCountries`, `mapCountryResponse`),
  существительные для данных (`CountryCard`, `SearchState`). Префикс `_` —
  для намеренно неиспользуемых параметров заглушек (ESLint пропускает).
